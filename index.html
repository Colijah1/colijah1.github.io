GDT5008 · Indie Game Design · Year 2

Echo Knight:
Lair of Drogo

The brief

Design and build a complete 2D game. I set myself a goal: create a challenging atmosphere with nothing but pixel art, tight controls and a high-stakes boss fight.

What I built

  • Movement that feels snappy: WASD, jump, a dash on left Ctrl for wide gaps, and multi-jumps for vertical climbs
  • Melee combat on left click, with hitboxes tuned until strikes felt powerful
  • An NPC owl who delivers the story and teaches the controls through dialogue
  • Enemies with "thick skin" that you defeat by stomping, so the mechanic is part of the story
  • A climb through frozen mountains to a final boss: the dragon Drogo, nesting in the caverns below

Design decisions

The first level works as a tutorial disguised as story, so players learn every mechanic before the difficulty rises. Music and character art from other creators are credited in-game.

CPU5004 · CodeLab II · Year 2

Pokédex
desktop app

The brief

Build a data-driven application. I made a Tkinter desktop app that wraps the public PokéAPI, so users can search Pokémon, browse types and species, follow evolution chains and save favourites.

Architecture

From the start I separated responsibilities so a 3,000-line project stayed maintainable:

Pokemon modelStores ID, name, types, abilities, base stats and sprites, normalised from the API. Helpers like get_stat and to_dict.
API managerAll HTTP requests and JSON parsing in one place: Pokémon, type, species and evolution-chain endpoints.
App controllerThe Pokédex class: every screen, interaction and piece of app state in the UI.

Why it matters

Keeping data, networking and interface apart meant I could change the UI without touching API code, and saving favourites was a simple to_dict call into a file. I explain the whole structure in a separate code walkthrough ↗.
